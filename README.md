# FA Foundry · 可追溯的 AI 财务分析师

把月结数字变成经营判断。FA Foundry 让 AI 直接读你们自己的月结套表，按财务的方法把利润偏离、现金、回款和全年预计算清楚，写成管理层能用的分析，每个数字都能点回 Excel 原单元格。分析由 AI 动手，口径、差异处置和结论由财务经理拍板。

**[产品介绍网页](https://fa-foundry.pages.dev)** · **当前版本 0.10.2** · [下载（GitHub Release，已签名公证的 macOS 应用）](https://github.com/ZCDeng/finance-skill-foundry/releases/latest) · 仅支持 macOS Apple Silicon

0.10.2 是修复加固版，功能与 0.10.0 相同：安装包发布前在干净环境里核对能独立运行（不依赖本机 Python 或 Homebrew，不连外网、不自动下载扩展，只含 Apple Silicon 程序）；月结锁定时导入的 CSV 先按 UTF-8 读、读不通再按 GBK，用友、金蝶或中文 Excel 导出的 CSV 不再报错。0.10.1 修复了 0.10.0 安装版收缴率计算报错的问题。

## 第一次使用

应用里内置了华宸物业（虚构的大型物业集团，住宅与非住宅混合业态，50 家城市公司）2026 年 8 月的示例资料。建议先在这套假账上把月结和经营分析走一遍，再导入自己的套表：

1. 打开示例任务，按指南「跟着做：华宸物业 8 月」十一步操作：从确认表结构、勾稽与差异处置、分析和文稿复核，一直到导入收费明细、按自己的口径调整收缴率，最后建 9 月练习任务试一次滚动到下月。每步写清做什么、在哪一页、应该看到哪些数字。
2. 每一步都可以「对照参考结果」：系统用当前版本把 8 月整条路线自动跑完（约 50 秒），勾稽 83 条、79 条相符、4 处差异写了处置理由，月结如实停在「差异待处理」。本该经理做的确认都标为「示例预置」，不冒充经理。
3. 导入自己的资料前，先看指南里的「导入前的资料准备清单」，按分析列出需要哪些列、在 Excel 里先修什么；在管面积台账、物业服务合同台账、人数三张补充模板可一键导出。

## 0.10 新增

- **内置示例与参考结果**：示例任务带「示例」标签；示例里确认过的表结构单独存放，不会套用到真实套表上；示例任务可一键换成新版或移进回收站。
- **指南「跟着做」十一步**：指南中的数字与引擎算出的结果由前后端自动测试核对，引擎或示例资料变了测试先报错，指南不会悄悄过时。
- **资料准备**：资料准备清单与补充模板；GBK 编码的 CSV 可直接加入；.xls 会提示先另存为 .xlsx；两行表头合成一个列名；看板页可「当作数据表」逐列确认，下月同形状的表自动采用。
- **收费明细与收缴率**：收费明细走单独导入通道进 DuckDB（CSV 含 GBK、可分多个文件、上限 500 万行）。收缴率按行业通行口径计算：比率按金额、应收取减免后净额；当期收缴率＝本年账期已收÷本年应收，清欠率＝本年收回往年欠费÷年初往年欠费，综合收缴率＝(当期已收＋本年清欠)÷(本年应收＋年初欠费)；预收冲抵到账单才算已收，作废冲红剔除。各家差异做成口径参数，不为某一家在代码里开分支。
- **口径按版本保存，经理确认**：收缴率口径每次修改都保存为新版本；助手可以识别字段、提议设置，只有经理能确认，未确认的结果标「试算」。资料页「收费明细与收缴率」面板可导入、逐张确认列、确认口径。
- **归档与回收站**：任务可归档、移入回收站和永久删除，操作后列表顶部可「撤销」；清空和永久删除前弹确认框写明数量。
- **工作区分区**：标题分三级、说明放在标题下；结果页底部「设置与高级」三个折叠；「…」菜单只留当前任务的操作，方法库、数据台、任务记录移到左栏底部；资料页分「资料」「范围」「更多操作」；指南新增「工作区地图」。

## 当前边界

截至 2026 年 10 月 9 日：

- 不连 ERP：读的是导出的文件，ERP 连接器只是占位，来源刷新没有在真实租户上联调过。
- 不过账、不付款：凭证只出草稿；现金预测是分析，不执行资金划拨。建账和银行资金操作保留独立扩展边界。
- 不重算 Excel 公式：导入用公式的缓存值；滚动生成的副本在 Excel 里打开时才重算。
- AI 文稿质量仍在爬坡：解释质量评测首轮主集 17/30、留出集 5/8，离 90% 的目标还有距离，经理校准评分尚未完成。每份文稿都要经理复核，月结页最高只推到「可提交经理复核」。
- 导入格式：.xls 需先另存为 .xlsx；单份资料上限 10 万行，收费明细上限 500 万行。
- 平台只支持 macOS Apple Silicon。随包表格预览组件的许可 2026-11-15 到期，到期后预览加水印，月结不受影响。

## 分析流程

1. 输入“华东利润为什么低于预算”等问题，或直接添加资料。首次使用无需先写 skill、配置科目表或锁定期间。
2. 添加 CSV、JSON、XLSX 表格，或 Markdown、TXT 背景资料。原文件复制为带哈希的资料快照；补资料增加快照，不覆盖旧数据。
3. 与助手研究问题。可以检索、检查资料、执行 SQL、运行隔离的 Python/Bash 脚本，也可以委派有明确范围的子任务。
4. 在“分析结果”检查来源、计算与执行状态，修改参数和假设后保存新版并重跑。高级 SQL 默认折叠。
5. 在“文稿”查看事实引用和质量提示，编辑后重检当前正文；有提示仍可保存草稿。确认专业判断后归档，导出 Markdown 或 XLSX。经理判断可按账套、组织和有效期保存，回到助手继续分析；旧稿和旧计算保留。
6. 有复用价值时再“保存方法”。下个任务提供新的资料绑定和参数后运行，不继承原任务的数据与结论。

财务经理决定口径、假设及文稿是否采用。系统分别记录执行、可复现性、用户判断和发布状态，不把程序运行成功当作业务结论正确。首次执行不会自动显示“可复现”；相同定义和输入的实际重跑一致后，才标记 SQL 结果可复现。

## 当前能力与边界

| 能力 | 当前行为 |
|---|---|
| 解释质量 | 事实占位符自动绑定精确引用；数字、单位、方向及当前稿引用检查；背景按当前任务授权与期间复用。检查未发现问题不等于经理认可或业务原因已证实 |
| 证据标签与时效 | 文稿每条引用和已引用事实按服务端记录（引用依据、计算、复算规则、分析要求、一致性核对、修订比较、资料时效）分为 12 类证据标签，并汇总为证据等级（可决策、研究级、初步、假设主导、无法支持）；保存与预览用同一规则，不按正文措辞判断（正文里没绑定依据的数字记为未知），也不采用调用方传入的标签；写明是用户假设或专业判断的引用即使指向某个结果也按假设或判断计，脚本输出没有通过的来源复算时记为未知。资料页逐份文件列出截至日、期间和时效（当前、资料过期、期间不符、未声明；分析期间还没确认时为无法判断），只比较声明的期间、截至日和已确认的分析期间，不用电脑日期，没声明就是未声明；系统刷新按刷新范围的期间判断，上月文件（包括同名的上月文件）显示期间不符而不是资料过期；已存文稿的时效和证据标签按读者能读到的资料得出：权限较窄的会话不会因为它读不到的新版本看到资料过期，经理读助手会话保存的文稿时，会话当时读不到的新版本照样算过期，保存之后才上传的文件不改变已存文稿的结论。证据等级是对依据的分类，不并入核验状态、月结顶栏或完成判断，「可决策」不代表经理认可；直接引用整本工作簿时，文稿里的时效不按其工作表重读，可能显示未声明；控制和月结页判断「资料已更新」仍按同名新版本，不区分期间，会话只按它能读到的新版本判断 |
| 外部报告复核 | 导入的 Word、PDF、PPT、Markdown、HTML 月报（PPT 只取文字和表格，不能导出为 PPT）可在采用前或保存后由经理点「复核数字」：逐个数字与当前有效的套表单元格、资料表和计算结果比对，分为一致、四舍五入后一致、疑似单位换算、不一致、需人工核对，并给出位置、原文片段和来源单元格。按数值和行名比对、不理解语义；同名项目只有单位和期间（本月、累计、预算等）都对得上才算不一致，否则列为需人工核对；OCR 无页码文字一律需人工核对；一份文稿只复核前 3000 个数字，超出时提示且不显示为全部一致；结果另存为记录，不改动文稿。复核只比对数字，不代表报告可以对外发送 |
| 财务分析 | 真实条件筛选、分组、预算差异、账龄与现金情景计算；示例验收使用合成资料 |
| 关联计算 | 声明快照、关联键和基数，检查重复计数；派生 CTE 的 JOIN 需先物化成快照 |
| 金额 | 导入和常规运算保留 Decimal；DuckDB 除法产生的浮点结果明确提示；XLSX 无法精确保留的长数以文本输出 |
| 工作簿公式体检 | 添加 XLSX 时顺带检查外部链接、迭代计算、隐藏工作表、跨簿引用、易变函数、公式里写死的数字（百分数按换算后的值判断）、公式里留下的 #REF! 断链、结果为错误值的单元格、无缓存值公式，以及同一行或同一列里与复制写法不同的公式（夹在中间或紧接在最后一格），结果随资料快照保存，资料页逐类列出并可打开原单元格；较早的工作簿可手动体检一次（只显示不保存）。只提示不阻断，原有导入拒绝规则不变；外部链接只记文件名，样例公式里带路径的文字显示为“…”；超过 10 万行或 256 列的工作表跳过并注明，最多检查 20 万个公式单元格，写法各不相同的公式很多时会更早停止并注明；不重算公式，“写死的数字”和“写法不一致”按固定规则判断：开头的期初数、引用本行或本列这些格的小计和合计不算，但有意设置的其他写法（例如从别处取数的小计）、有意返回的 #N/A 结果仍会列出，可能有误报或漏报，是否修改由经理判断 |
| 脚本 | macOS 系统隔离、冻结输入、独立工作目录、资源上限、代码/环境/产物哈希；归档输出可打开 |
| 后台任务 | 查看、取消、重试；重试创建新记录并沿用原输入；取消回收脚本进程 |
| 子任务 | 真实 spawn/fork，冻结父任务上下文，有深度与工具范围限制；记录结束状态 |
| Office | 隔离 Python/openpyxl 生成或修改工作簿成果，原始快照保持不变；可导出、打开后重新导入 |
| 下月套表滚动 | 资料页「滚动到下月」按「来源到单元格」映射，把本月数（资料单元格、区域合计、计算结果或手填值）写进上月套表的副本：先预览，只写普通单元格并保留其数字格式；公式、数组公式、合并单元格非左上角、受保护锁定格、错误值、会把数字格变成文字的值（例如「1,200」）和写进日期格的数字只列入清单不写。生成和导出副本只能由经理操作，生成前复核每个来源，原快照不变，副本登记为新资料并逐格留变更记录，可导出到自选位置在 Excel 里打开；模板只存映射和文字提示（其中数字都换成 #），不存当月资料和手填金额，套用时工作表名按位置换成本月的。不做公式重算：副本公式在 Excel 打开时重算，保存后重新添加才能读到结果；含图表、图片、批注、外部链接、宏，或迷你图、部分下拉列表、条件格式等扩展内容的工作簿只给「需手工填写」清单、不生成副本；工作表名不会改 |
| 方法 | SQL 方法显式保存，移除注释与具体字面值，跨任务重新绑定；脚本暂不保存为方法 |
| 财务方法技能 | 随包提供 financial-statements、variance-analysis、reconciliation、journal-entry 四项方法，以及 setup、close、bva、cash 四个路由包；分析会话可发现并加载正文与配套说明。连接器占位不代表已连接 ERP，分录技能用于草拟。随包技能的措辞由契约测试把关：不声称已接通 ERP、能过账或付款，斜杠命令和正文里反引号标出的工具名必须真实存在；这只检查文字，助手的回答仍需经理核对 |
| 差异类型与可用结论 | 每项勾稽差异可标问题类型（公式或控制缺陷、来源矛盾、无依据假设、未更新、口径不同）：助手只能建议并附理由，经理在界面采用或改选才算定下；类型绑定当时那笔差额，确认或修改控制后仍跟随同一检查。月结页另给整套表和逐个工作簿的可用结论（可用、带保留可用、不可用、无法判断），只按经理确认的控制和处置得出，类型和助手建议不改变级别；它不替代顶部状态，也不代表经理复核或业务原因已证实 |
| 后续领域 | 总账、凭证过账、银行支付尚未实现；现金预测属于分析，不执行资金划拨 |

脚本隔离目前只支持 macOS；其它系统拒绝执行，没有静默降级。Bash 支持受限命令，不提供任意子进程或网络。工作簿生成不包含 Excel 公式重算引擎；带公式但缺少缓存值的输入会明确报错。日常回归使用确定性适配器；真实模型验收另用显式 `--live` 入口，在临时配置中使用已有 provider 和合成资料。每次实测分别记录模型、技能来源、计算和草稿。新版解释质量的功能验收、首轮模型成绩和边界见 [解释质量交付记录](docs/finance/explanation-quality-delivery.md)；历史基线见 [r2 实施记录](docs/plans/2026-09-06-finance-r2-execution-log.md)。

## 数据与调用边界

```text
var/tasks/<task_id>/
  task.json, windows.jsonl, sessions.jsonl, deliverables.jsonl
  analysis/
    datasets/           # 原始资料与元信息、哈希
    revisions/          # 不可变计算定义与版本
    runs/               # 实际输入、执行结果与状态
    drafts/             # 文稿版本、来源与用户判断
    methods/            # 显式保存的复用方法
    jobs/               # 后台/子任务运行记录
```

`foundry/` 统一负责数据读写；Electron 与插件调用 CLI，不另建数据库入口。每次助手调用以服务端登记的 session 解析 task、workspace 与资料范围；未知 session 拒绝执行。A→B→A 切换不会让 A 的会话落到全局 current 指向的 B。父任务补资料后可以显式刷新上下文，已派出的子任务保持原资料范围。会话读到的每条记录都按它的资料范围得出：读不到上一版的修订按没有上一版显示，沿用了上一版内容（标题、正文、引用、附注、计算依据、取数配方、核对规则、重要性等）的修订则不显示；分析要求核对只计文稿引用的运行和只读要求资料（及所引运行资料）的运行，完成回执、勾稽控制结果和月结状态不因范围外的文稿、运行或新版本而改变；当前要求版本在范围外时会话不能保存文稿，导出登记只由桌面端做。

新任务默认使用 `analysis` preset，工具通过相同的数据与执行边界开放。旧 `period` / `f3` 和技能创作保留在“旧版期间流程”中，便于处理已有窗口。旧命令详见[期间流程参考](docs/legacy-period-workflow.md)。`mark-done` 的合同校验、引擎样例通过与方法实际执行分别报告，不能互相替代。

## CLI 示例

```bash
foundry --var VAR task-new --title "华东利润与预算分析"
foundry --var VAR --task TASK dataset-add --path actual.csv --name "本月实际"
foundry --var VAR --task TASK analysis-state
foundry --var VAR --task TASK analysis-save --spec '{"question":"经营利润","bindings":{"actual":"SNAPSHOT_ID"},"sql":"SELECT revenue-cost-expense AS profit FROM actual"}'
foundry --var VAR --task TASK analysis-run --analysis ANALYSIS_ID
foundry --var VAR --task TASK analysis-draft --spec '{"title":"经营简报","body":"可编辑的管理层判断","run_ids":["RUN_ID"]}'
foundry --var VAR --task TASK analysis-export --draft DRAFT_ID --format xlsx
```

`--var`、`--task`、`--session` 是全局参数，放在子命令前。应用原生选文件是受信任的用户操作；助手只能导入已登记工作目录内的资料。

## 开发与打包

依赖以 `pyproject.toml`、`uv.lock`、`app/package-lock.json` 为准。当前固定 harness 为 `@deepseek-ai/dsh@0.1.1-rc.2`。没有为本轮新增第三方依赖。

```bash
uv sync --extra dev
cd app
npm ci
npm run harness
npm run foundry
npm run formulator
npm run package
```

`npm run package` 检查 runtime/冻包版本，实际启动冻结的 Data Formulator 校验 connector，再构建 macOS 应用。`npm run foundry` 使用 PyInstaller one-dir，校验冻结引擎及真实脚本隔离。产物在 `app/release/`，构建脚本不会安装或覆盖 `/Applications`。
