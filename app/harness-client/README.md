# Embedded client contract

This app embeds the pinned DSH runtime and its native conversation. `scripts/adapt-harness-client.mjs` is a replayable, SHA-256 checked adaptation of four exact client bundles. It preserves native session binding, command arbitration, admission, queues, streaming, approvals, `ask_user`, settings, and tools. It does not implement a second chat protocol.

Run `node scripts/adapt-harness-client.mjs` after staging to apply or update the adapter. `node scripts/adapt-harness-client.mjs --check` and `fetch-harness.mjs --check` are read-only package gates. Stock sources and previous generated digests live under `extra/dsh/.foundry-client-stock`; source changes unknown to those checks refuse to overwrite. A new upstream version requires deliberate reinspection, new pins, and regression tests.

The layout retains the declared slot tree. Its sidebar owner renders the native settings slot only, so the app task list remains the sole root-session navigator. Native details occupy the full conversation rectangle at 400/460 px, have the stock close control and Escape, and return focus on close. The hidden center remains mounted. Native settings use horizontal section navigation. The large coding hero and workspace picker row are replaced with a compact finance empty state; the workspace requirement itself remains unchanged.

`window.__foundryEmbedded` accepts only a session id, an optional draft, and an optional explicit submit action id. It uses the runtime's session selection and resident input actions. Passive resume never writes a draft. Follow-ups append to existing unsent text. Admission observation records the existing machine's accepted `submit-settled` event after its phase/sequence guard. A success receipt is written only after native success; known failure releases the retry cache. In-flight retries wait on the same attempt. A receipt whose old runtime disappeared is unresolved and cannot automatically resend; the user can inspect the conversation and use its native composer. This is an at-most-once retry boundary, not a claim of distributed exactly-once delivery.

The Electron host validates layout rectangles, converts renderer CSS coordinates using the sender's actual zoom, clamps to the window, and rejects stale revisions. Showing/hiding or resizing retains the WebContentsView. A requested input focus is deferred while hidden; passive resume and geometry updates do not request focus. Same-origin session selection never reloads. A runtime port change migrates the full touched chat stores and admission receipts before new stores hydrate.

WebContentsView is a native layer. React z-index cannot cover it: the app must call `setVisible(false)` before global shell dialogs, preserve its requested rectangle while hidden, then apply accepted geometry before `setVisible(true)`. A zero-sized rectangle alone can leave a stale macOS compositor layer visible; it is not proof of hiding. Native tool details, menus, permissions, and questions stay inside the pane. Native file dialogs remain above native views. App shell drag handles must sit outside the accepted native rectangle. Geometry revisions must increase across task changes, not restart per component mount.

The font file is copied from the checked offline Noto Sans SC asset and injected as a WOFF2 data font by the host. No font server, installed-system font, or runtime download is required.

Packaged verification scripts in `tools/verify_native_workspace.cjs` and `tools/verify_ui_workspace.cjs` exercise 400/460 px settings/details, exact session binding and resident drafts, focus, native visibility, zoom, theme, retry admission, and Chromium composition. The latter captures the macOS window including native layers: BrowserWindow.capturePage alone omits WebContentsView and is insufficient for stacking review. Tests clear Playwright's per-page color-scheme override before testing system theme. Remaining boundaries include real provider streaming and task switching during a live model run, physical macOS IME candidate windows, and externally effective permission/ask_user workflows. Synthetic admission success is labeled and makes no claim about provider availability.
