# 文稿图表方法

此说明适用于 Foundry analysis 模式。加载相应财务技能后，可用 `method-resource {skill: "financial-statements", resource: "report-visuals.md"}` 读取；不会扩大期间锁表模式或当前任务的数据权限。

## 先选读者要比较的关系

| 阅读目的 | 当前可用方式 | 边界 |
| --- | --- | --- |
| 比较项目、组织或实际与预算的大小 | `bar` 横向条形图；多个数值列自动分组 | 1–3 个可比系列；类别数×系列数（含缺失位置）最多 12；长名称优先横排 |
| 比较同一口径随时间的变化 | `line` 折线图 | 最多 24 个时间点、1–3 个系列；由运行结果排好时间顺序，空值留缺口 |
| 解释处理步骤及相邻步骤的关系 | `flow` 解释流程图 | 2–6 步；写明关系和解释来源，不据流程箭头认定因果 |
| 查精确数值，或类别、系列超出限制 | 表格，或有明确口径的多图 | 不把完整数据静默截断为前几行，不为凑图补零或虚构“其他” |
| 只有一个重要数字或没有明确关系 | 一句话或列表 | 不为装饰生成图形 |

每稿最多 20 张图。图题、类别、数值、来源与步骤说明共同计入排版密度；单图超出 960×1200 的布局范围时，缩短文字或拆分，不裁切内容。

图型用于回答问题。当前实现只有上述三类结构图表；不声称支持上游完整图型集、任意 SVG、地图、桑基图或动态交互。

## 数量图必须来自已保存的计算

1. 读取当前任务已有成功运行，核对类别列、数值列、币种、单位和比较范围。缺少合适结果时先保存并执行分析；需要转置、排序、汇总或过滤时，计算产生一份可追溯的新结果，不能只改图上的标签。
2. 调用 `chart_deliverable_save {spec: {run_id: "实际运行 ID", label: "图表来源名称与期间"}}`。它冻结运行结果和资料快照；归档图不替代财务要求、claims 或来源复算。
3. 在 `save_explanation_draft.spec.document.content` 中插入 `reportVisual` 节点，选择返回的 `chart_id`、类别列 `category` 和 `value_columns`。先用 `prepare_explanation` 准备正文事实；图中的数量来源仍由归档运行解析，不手抄数值。
4. 服务端从当前任务归档图覆盖并冻结 `series`、`run_id`、`snapshot_hash`、`source_label`。新建或修订时模型均不填写这些服务字段，也不传任意路径、预览句柄、HTML、SVG 或外部数据 URL。
5. 保存后核查当前文稿与图表。修订沿用现有 `parent_id` 版本规则。修改数据或假设要先生成新成功运行和归档图，再更换引用；改图题或图型仍保存文稿新版。

类别不能为空或重复；数值列必须为数值或 `null`，不能全空。负值、零值和缺失三者不同：负值在零线另一侧、零保持真实零、缺失不连线也不补零。数值保留原精度供数据表核对。`unit` 仅声明共同展示单位，不做数值换算；金额、比率、数量及不同币种或口径不得因为能画在一起就视为可比。比例的分母和比较范围写在正文或图注附近，财务报表不凭空添加调研样本量 N。

## 图表、结论和来源一起保存

每图一个主题。`title`（最多 160 字）说明比较对象和期间，`takeaway`（最多 300 字）写有依据的阅读结论或限定条件；不填 `{{fact:...}}` 占位符，不把算术贡献写成经营原因。需绑定事实的具体数字放在正文 text 节点中，用原有事实占位符与 claims 核验。

数量图的来源名称来自归档图，运行与快照由服务保留；不要把来源标签当作“已审阅”证明。流程的 `source_label` 默认“作者分析”；外部参考写明作者/机构、出处和检索日期，经理假设或判断在正文显式归类，不伪装为计算证据。`connector` 说明与下一步的关系，最后一步的 connector 留空；箭头只是作者表达的关系。

沿用应用主题、离线中文字体和固定版式：直接标注系列和数值，文字与图形留足间距，图例不遮住数据，语义颜色不代替标签。颜色区分真实系列或口径，不用红绿擅自判定“好坏”。默认保留零基准；不使用 3D、双轴或装饰性光晕。内容过密时先改组织方式，不能缩到看不清或删掉不利数据。

## 结构文稿示例

将下面的 ID 和列名替换为当前任务真实返回值；示例没有任何可直接引用的财务数值。

```json
{
  "spec": {
    "title": "经营分析",
    "body": "收入对比",
    "document": {
      "schema_version": 1,
      "template_version": "annual-v1",
      "metadata": {"currency": "CNY", "unit": "万元"},
      "content": [
        {"type": "paragraph", "content": [{"type": "text", "text": "收入对比及适用范围。"}]},
        {"type": "reportVisual", "attrs": {"visual": {
          "version": 1, "kind": "bar", "title": "同期间各组织收入与预算",
          "takeaway": "请结合正文中的预算口径和未确认事项阅读。",
          "chart_id": "归档工具返回的真实 ID", "category": "organization",
          "value_columns": ["actual", "budget"], "unit": "万元"
        }}}
      ]
    }
  }
}
```

传入 `document` 时，服务从结构内容生成正文；`body` 仍按工具要求传入，不另写一份相互矛盾的正文。普通 text 节点继续支持 `{{fact:FACT_ID}}`。流程节点的 visual 改为 `kind: "flow"`、`title`、可选 `takeaway`/`source_label`、`steps: [{label, detail, connector}, ...]`；不填写 chart_id、category、value_columns 或数值系列。

## 保存与导出检查

阅读和 HTML/PDF 使用受控 SVG；DOCX 保留等比图像及图注；Excel 数量图同时给原生图表和精确数据，流程保留步骤与关系；Markdown 保留数据表或流程文字。导出后不保证能重新导入为原生可编辑图表，结构文稿版本才是可继续编辑的原件。核对图题、单位、结论、来源、缺失与负值，以及完整数据未被裁切。
