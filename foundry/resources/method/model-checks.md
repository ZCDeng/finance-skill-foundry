# 财务模型检查和可复核结果规范

版本：finance-methods-20261023。本目录规定应检查什么，不宣称所有检查已有自动执行器。
按当前工具能力选择已有控制、run、来源检查和工作底稿；未支持项明确记录，不能通过模型自述变成通过。

## F11 检查流程与记录

输入：文件/数据 hash、检查范围、适用任务与口径、模型版本、公式/缓存、关键输出及基线。
顺序：输入完整性 → 结构/公式 → 财务恒等式 → 扰动/滚期 → 来源证据 → 实际目标计算引擎 → 专业复核。
不同层次分别留证，模型自己复述“已检查”不构成任何层的执行记录。

每项覆盖记录至少有以下字段，可放在既有底稿或结果的结构化附表，不创建第二套批准数据库：

| 字段 | 含义 |
| --- | --- |
| check_id / version | K编号及规则版本 |
| method / profile / rule_dependencies | 适用方法、口径及实际相关规则，不能引用未确认身份 |
| status / severity | pass、fail、unavailable、not_applicable、stale；按影响标重要程度 |
| coverage | 输入行/表/期间、公式扫描数、排除项、截断和实际检查范围 |
| source / run / locator | 当前不可变来源、运行、表/行/列/公式位置 |
| expected / actual / difference | 期望、实际、差异，缺失用明确不可得，不能补0 |
| unit / currency / tolerance | 单位、币种、绝对容差及精度/批准来源 |
| execution / limitations | 程序、计算引擎及版本、时间、未做部分 |
| reviewer / decision / evidence | 仅真实授权复核填写；助手不得伪造具名签收 |

现有 break 映射为 fail；保留底层原始错误代码，不能把任意运行错误都美化成缺资料。
not_applicable 必须有可核实的适用条件和理由。缺缓存、读取失败、未运行、未覆盖、截断、不可用重算引擎不能标为 pass。
外链/隐藏表警示不自动阻断全部导入，只限制其影响的结论。检查通过与经理确认分开。

## 精度和重要性

原始金额使用 Decimal 和来源单位；展示舍入不反向改原值。代数恒等式默认零差异。
不同来源已量化时可记录有依据的绝对容差，说明单位/精度/批准来源；沿用现有控制对显示舍入噪声的明确处理。
不得统一硬编码0.01、按大额比例掩盖错误，或用重要性门槛放过假来源、重复记账、越权和错误算术。
数值0、空缺、零分母、负数与读取失败必须区分。

## K01–K24 目录

| ID | 通过条件与证据 | 失败/缺口处理 |
| --- | --- | --- |
| K01 | 准则×方法×用途×生效期间受支持，必要政策已有效确认 | 未知组合限制专业声明；普通算术可独立进行 |
| K02 | 实体、单体/合并、币种、单位、符号、含税基础一致 | 留转换证据，不直接混加 |
| K03 | 单月/YTD/TTM与余额期间明确，实际预测不重叠 | 缺月/混期停止对应比较 |
| K04 | 行数、控制总额、唯一键、状态和排除范围可重建 | 披露不完整覆盖，不能内连接删差异 |
| K05 | 缺失、真零、零分母、负基数和可比范围分别处理 | 保留明确缺口，不猜值 |
| K06 | 扫描范围无影响关键结果的断链/错误缓存；公式覆盖与可信模板或前版比较 | 无基线不能断言常量曾被覆写，不能称全面审计 |
| K07 | 外链、隐藏表、硬编码、迭代、截断均披露 | 未检查部分 unavailable，不自动联网读外链 |
| K08 | DAG输入完整、引用有效、无环，输入/公式/假设互斥 | 循环 unsupported，不启用隐式迭代凑平 |
| K09 | 数量×价格与声明金额相符，各项差异精确闭合 | residual不能改名mix；可比性不足单列 |
| K10 | 每条对账输入唯一归入匹配或未匹配，可重建双方总额 | 禁止重复键放大、任意多对多配组 |
| K11 | 本位币借贷平衡，原币/汇率可查，计提/冲回/账单/付款无重复 | 未知折算或未支持路径不得假通过 |
| K12 | 期初＋有据变化＝期末，AR毛额/准备/净额分别闭合 | 禁止无来源plug，争议项不自动删除 |
| K13 | 收入、账单、收款、合同资产/负债与VAT分别解释 | 预收不等于收入，税因子不可默认全业务统一 |
| K14 | 银行在途已入账不重复调整，GL漏记/截止另列草稿 | 不能统一等1–5天，记录实际清算证据 |
| K15 | PPE成本、累计折旧、净值和现金capex调节一致 | 在用日不等于未经确认的折旧开始政策 |
| K16 | 债务期初＋借入−本金偿还±有据变化＝期末，利息分开 | 未承诺融资不填缺口 |
| K17 | RE期初＋净利−股利±批准调整＝期末，OCI分开 | 禁止RE凑平资产负债表 |
| K18 | 期初现金＋CFO＋CFI＋CFF＋FX＝期末，现金范围可调节到BS | 不省略FX，不能默认为全部账户可用 |
| K19 | 每期资产＝负债＋权益，每个余额都有来源或受支持公式 | 单纯算平不足以证明财务逻辑正确 |
| K20 | 可用现金扣除确认受限项，内部转账不双计，融资承诺明确 | 周内安全需日期级检查，周末正数不能替代 |
| K21 | 扰动只影响正确路径，旧AR回收与新销售作用不同 | 平衡但不传播仍fail |
| K22 | 换期不覆盖历史实际，不漏期/重计累计，不偷移原输入 | 生成后继运行并保留旧快照 |
| K23 | 声明的目标Excel/其他引擎真实重算基础及代表情景，记录版本 | 可读缓存不等于真实重算；未运行输出未验证草稿/值表 |
| K24 | 来源/相关规则变化使依赖结果、接受差异、completion和月结重新核查 | 无关规则不全局失效，旧归档保留历史身份 |

## 输出和恢复

输出范围/版本、关键结果、逐项覆盖、异常位置、差异、严重度、可编辑假设及来源定位。
现金、权益或“其他”不得作为调平数；模型正确性还需检查预收当收入、费用不当资本化、旧AR当新销售、受限现金当可用资金和删除争议AR等算平但业务错误的反例。

模型公式工作簿只有在目标引擎真实重算后才能声称该引擎验证；静态值表不能改称交互敏感性模型。
修复公式先冻结反例，再修公共规则；新来源或规则通过新版本重核，不改旧检查历史。
人工接受差异必须有真实理由/范围，不能覆盖错误算术或外部过账权限。Foundry does not post or pay.
