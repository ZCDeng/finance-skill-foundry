## Purpose

This fixture is the r4 blind set for finance explanation quality. The existing
30-case suite and 8-case holdout suite are now regression material because they
have already shaped implementation and repair decisions. These 20 cases were
created as new synthetic cases before any tuning result from this set was seen.

No model calls were run while creating this fixture. The only validation was the
current fixture schema check plus local duplicate checks against the existing
30+8 cases.

## Validator Compatibility

The current `tools/verify_finance_evals.py` loader has only two suite branches:
the default main suite, which requires 30 cases and stage5 coverage, and
`suite: holdout`, which requires at least 8 runnable cases. To avoid modifying
the scorer or production code, this r4 blind fixture uses `suite: holdout` while
preserving its blind identity in the file path, version, and this contract.

This is a schema compatibility choice, not a statement that the old holdout set
remains blind. The old holdout remains regression coverage.

## Coverage

The fixture contains 20 runnable cases:

- `profit_bridge`: positive, flat by offset, loss narrowing, loss widening,
  prior-period comparison, missing-budget-as-manager-zero, duplicate row
  exclusion, account-code mapping.
- `price_quantity`: `quantity_then_price`,
  `base_weights_with_interaction`, negative interaction, volume-down and
  price-up cases.
- `price_quantity_missing`: amount-only data that must not invent quantity or
  price.
- `ratio`: cost-rate decimal presentation.
- `control_totals`: three-currency control totals without mixing currencies.
- `account_total`: cash as a stock balance across periods.
- `receivables_aging`: cutoff boundaries, active-only status filtering,
  mixed currencies, and not-due treatment.
- `cash_13_weeks`: week-one cash, delayed receipts crossing weeks, and
  organization scope filtering.

The r4-specific stress points are zero materialization, offsetting drivers,
loss wording, status filters, currency identity, cutoff boundaries, cross-period
cash activity, manager judgment labels, and requested drilldown targets.

## Freeze Rules

- Do not edit this file after a blind run has started. Create a successor
  fixture version instead.
- Do not tune prompts, production code, or scorer behavior using this fixture
  and then report the same file as blind.
- If a schema blocker is discovered, report it as a fixture or scorer-contract
  blocker. Do not mark non-runnable cases as runnable to satisfy coverage.
- If a case fails because the product lacks a needed r4 capability, keep the
  failure as product evidence unless the case is found invalid under this
  contract.
