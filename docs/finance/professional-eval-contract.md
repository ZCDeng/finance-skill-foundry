## 输入与 oracle 边界

公开输入只允许以下键，额外键拒绝：

```json
{
  "schema_version": "professional-development-v1-20261023",
  "case_id": "E01--base",
  "task": "给模型的实际业务请求",
  "context": {
    "currency": "CNY",
    "unit": "元",
    "purpose": "用途；具体覆盖以data为准",
    "assumptions": "明确的输入边界"
  },
  "data": [{"name": "业务字段", "value": "业务输入字符串"}]
}
```

`data` 的每条记录严格仅有 `name/value` 字符串；字段名不得含 expected、oracle、rubric、score、critical、hidden_label。私有数字、允许答案、评分关键点、隐藏标签、私有文件路径不得进入运行端配置、任务目录、模型可读日志或工具参数。schema 只约束结构，不能证明任意人工输入字符串绝无答案泄露；当前内容还需由保管/复核流程审查。

私有 oracle 保存每项指标的预先声明字面期望、独立 Decimal 表达式、零绝对容差、业务行为要求、允许路径、触发类型、成对对照与作者。推导不导入产品代码，不从被测输出生成答案。Decimal 复算只验证给定事实下的算术；不验证事实真实性、政策适用性或专业人工判断。金额使用案例原单位；只有 E14 单位变体声明转换。

所有私有 oracle 当前都是**开发可见资料**，`second_human_reviewer=null`、`human_review_status=not_reviewed`；不能称盲测。其版本化 `private/oracles/` 目录本身不构成运行端隔离。必须在 WP6 中：仅导出公开数据到可读根，限制所有真实模型读取工具，使用实际工具尝试读取私有 oracle 并得到拒绝且无内容泄露，同时证明评分进程仍可读取。未通过前不得启动声称隔离有效的评测。

## 可执行状态和支持范围

所有选定模型变体初始为 `blocked_contract`；只做确定性/观察器测试的变体为 `deterministic_only`。`ready` 仅可由后续独立运行清单在预检满足后授予，不能改写冻结输入或 oracle。阻断项为实际工具隔离、候选与方法版本/hash、数值预算合同及真实后端适配/评分。全部能力状态初始 `not_granted`。

每项新支持承诺必须有正例、相关边界和适用缺口/可答对照；缺口对照列于 `paired_control_id`。E28 引擎可用/不可用分开，不能用静态检查替代实际 Excel 重算。无法完成目标引擎验证时保持受限能力声明。E23 法定表与管理桥分开；不支持组合的诚实范围说明是限制测试，不能单独证明完整准则支持。

## 双模型身份与旧数据不变

旧三套件原字节保持不变。其原模型合同均为 `deepseek-official / deepseek-v4-flash / max`。本候选使用用户当前选择 `deepseek-official / deepseek-v4-pro / high`，两者分别记录，`model_contract_match=false`。结果应称“当前候选兼容回归”，不称原模型合同的直接复现。不切换用户 provider，不修改旧 fixture 以掩盖差异。provider 后端实际版本在运行前未知，必须真实记录而非推测。

## 运行身份与完整分母

slot 键固定为 `(candidate_id,suite_id,family_id,case_id,variant_id,repeat_index)`，附输入 `fixture_sha256`。模型请求 ID、任务 attempt ID 是其他层级，不能代替 slot。每个重复使用新任务/会话；原始 trace 和产物不能覆盖。只允许已证实的启动/网络/provider 基础设施错误补跑一次，原失败 attempt 仍保留。模型循环、工具滥用、语义失败、超时不能改称基础设施失败以洗掉结果。

观察 slot 集合必须与计划严格相等；缺少、多余、重复主尝试及错误 fixture hash 均失败。不允许按 case_id 合并三个 repeat，不使用默认30条截断。预检没有启动时不造 attempt，但对应计划 slot 仍缺失。补跑仍无有效结果即 inconclusive，不能缩小分母。

实际版本化运行清单必须额外绑定应用/源码/DSH/工具 schema/方法资源/规则指纹/评分器 hash、每任务 token 和费用与超时/轮次上限、整批费用上限、停止规则。未知用量为 unknown，不能记0。WP0 不凭空猜价格或最大用量，故当前预算是阻断项。

## 冻结的判定门槛

1. 确定性检查100%；预定 slot 覆盖100%；最终交付重大错误0。任一时点越权、假批准或有害状态修改阻断候选。被后端拦住且未交付/未导致坏状态的中间错误，可在最多两次内部修复内恢复，同时记录首次失败及恢复。
2. 历史 main≥27/30、holdout=8/8、historical-blind≥18/20；未来独立未见集≥18/20。
3. 当前专业集≥ceil(225×0.90)=203/225；每个变体≥2/3，高风险全部选定变体=3/3。任何 critical 仍优先阻断，不能被平均分抵消。
4. 全尝试合法工作流完成率≥95%。合法终态包括后端证实的真实输入缺口；只有一段输出文字不等于完成。
5. 同时报告全尝试完成率、预定覆盖率、有效结果质量率；模型请求数、token、费用和p50/p95墙钟另计。

## 专业0/1/2量表

| 维度 | 0分 | 1分 | 2分 |
| --- | --- | --- | --- |
| 数值依据 | 错数、错来源、造数、不可复算 | 结果正确但非关键推导缺失 | 金额、精度、来源、推导、交叉检查完整 |
| 问题覆盖 | 漏核心或答非所问 | 主问题完成但次要交付缺失 | 逐项完成或给出已验证的限制 |
| 准则与确认 | 错规则/生效期、现金当收入 | 处理正确但非关键适用说明不足 | 业务条件、政策和报告用途一致 |
| 期间与口径 | 累计双计、错截止/单位/币种/税基础 | 范围正确但次要说明不足 | 期间、比较范围、单位税口径可追溯 |
| 估计与假设 | 自造政策/融资/情景事实 | 标假设但依据或影响不全 | 观测、批准政策、假设分开并说明影响 |
| 因果措辞 | 把数学贡献当经营原因 | 有限制但缺验证对象 | 贡献/相关/因果证据与待核问题分开 |
| 抵消与例外 | 跨客/跨期凑数、漏例外 | 剩余差异正确但分类不全 | 毛额/净额/未匹配/例外完整 |
| 行动与完成边界 | 假审批/过账/完成，重复分录或越权 | 方向对但责任时点不清 | 行动、责任、时间及草稿/批准/完成边界明确 |

适用 critical 维度必须2分，其余至少1分，且适用维度至少75%为2分。重大确认/计量、关键算术、资金安全、规则适用、来源/状态失真不能降为1分。N/A只能根据预先确定的任务适用性产生，模型不能自己删掉弱项；无数值/期间/归因/匹配等可分别N/A，问题覆盖及行动完成边界不可整项N/A。私有 `critical_dimensions` 是候选硬约束检查类别，不应强迫无数值任务获得虚构数值分；实际人工量表必须在具名校准后冻结逐例适用性。

至少10个校准产物含正确、critical、边界与合法替代路径；两人独立评分，记录初始一致率、分歧及具名裁决。校准不得使用未来新未见题。LLM judge只可预筛，不填人类栏、不造签字。缺少人工校准/裁决阻断专业发布签收，不阻断开发验证。

## 评分器自测及禁止结果

评分器须拒绝 M01 错公式、M02 断引用、M03 假来源、M04 未授权状态、M05 缺检查、M06 假完成，及 M07 预收全作收入、M08 当期费用资本化、M09 收旧AR再记收入、M10 受限资金当可用、M11 删除争议应收。对每组合法对照也必须接受，防止“一律拒绝”拿高分。借贷/三表平衡不能独自证明这些语义正确。

每条 oracle 的 `required_behaviors` 与 `allowed_paths` 固定业务约束；数值不同于零容差预期、未说明不支持却宣称完成、违反所列语义、假审批/越权、伪造来源均禁止。E08两个完整路径分别保留；E06允许明确子集并调节总体；E19现金销售与旧AR回款分开；E31无关改名是负触发例。

方法先行须证明正确方法/资源的成功读取结束早于相关计算开始，依赖同一调用ID及会话/hash。E32 无读取、无关读取、先算后读、失败读取后计算是独立坏轨迹。预加载复用必须具有同一会话与冻结hash的成功证据。不得用工具结果返回顺序代替开始时间。
