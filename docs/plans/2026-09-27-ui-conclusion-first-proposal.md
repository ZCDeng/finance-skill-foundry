# FA Foundry 结论优先 UI 方案

用户是财务经理。打开分析结果，先要看到答案，再决定要不要查依据、改口径。

[09-06 提案](2026-09-06-ui-interaction-design-proposal.md) 已经定过「先看到结果，再按需检查定义」。之后 R2、R4 和华宸修复陆续加了财务口径、考核调整、归档图、重要性阈值、质量检查、分析要求。这些面板大多插在结果上方或旁边，首屏又被过程和配置占满。

本方案把每个界面拆成三层，按层决定默认显示什么。2026-09-27 用户确认按本方案执行，先做 P0。

## 1. 清点结果

逐块清点了三个页签的渲染顺序，关键结论回代码核对过。

| 问题 | 证据 | 对经理的影响 |
| --- | --- | --- |
| 结论压在下面 | 第一个业务数字前有 5 块：口径设置、考核调整、归档图、版本选择、运行头（[Analysis.tsx:404](../../app/src/views/Analysis.tsx) 渲染在 RunPanel 之前）。没有成功运行时口径表单自动展开，结果前多 9–11 个字段 | 点进分析结果，首屏看不到数 |
| 没有一句话结论 | 后端 `finance_variance.py` 返回 `interpretation`，前端从未渲染。预算桥只有表格，没有关键数 | 经理要自己读表得出结论 |
| 状态词过多 | 文稿质量检查同时列 3 项核对和 4 个核验维度，共 7 个状态词 | 分不清哪一项要自己处理 |
| 技术标识露出 | 4 处显示 12 位版本号；重要性阈值下拉写 `baseline_abs`、`absolute`；考核调整写 `pending` | 读起来像开发工具 |
| 长操作无反馈 | 财务运行、ERP 来源刷新、工作簿写回、表结构确认只把按钮变灰；运行成功的提示放在运行后自动折叠的设置区里 | 点了运行，看不出有没有在跑 |
| 成果库列错 | 列是 时间 / 任务 / 类型 / 成因 / 会话 / 大小 / 摘要；文案里有「锁库」「窗口」 | 找不到要交付的那一版 |

用华宸 QA 任务的数据副本在开发版里看过一遍，又补了三条。脚本结果表的列名 `value`、`currency`、`metric_label` 和指标值 `revenue_variance` 都直接显示英文。情景写成 `actual_1_8`、`budget_1_8`，关键数卡片认不出来，一张都没出。脚本的原始输出（`14|revenue|集团合并|…`）默认展开在结果下面。

## 2. 三层规则

| 层 | 默认 | 放什么 |
| --- | --- | --- |
| 结论层 | 首屏展开 | 一句话结论、关键数、一行状态、下一步动作 |
| 依据层 | 点一下打开 | 结果表、来源行、引用事实、下钻 |
| 过程层 | 折叠 | 口径表单、阈值、SQL、版本号、运行历史、核对明细 |

结论里的每个数字都取自后端结果，前端不做金额运算。[Analysis.tsx](../../app/src/views/Analysis.tsx) 已约定 Decimal 字符串不经过 `Number`，结论条沿用这条。识别不出结构的结果不出结论条，沿用 09-06「不编造指标卡」的约定。

状态只改显示。执行、可复算、经理阅核、发布四个状态在数据层继续分开记录（见 [PRODUCT.md](../../PRODUCT.md)）。汇总句逐项点名还缺什么，不给一个笼统的「已验证」。

## 3. 改动清单

### P0

1. **重排分析结果页。** 已有结果时，结果面板在上，财务口径、考核调整、归档图收到结果下方。考核调整和归档图改为折叠区，摘要写明待确认条数和已归档张数。还没有结果时，口径设置留在上方，只露实际资料、预算资料、期间，其余范围字段进「更多范围」。
2. **结论条。** 预算桥取后端给的 `amount_change_display`，一句话写利润变化，再列收入、成本、费用各自的变化。`interpretation` 放在下方作限定说明。多组比较时逐组列出，最多 3 组。
3. **质量检查汇总成一行。** 7 个状态词收进「核对明细」折叠区，首屏只留一句待处理项。
4. **长操作补运行中状态。** 财务口径的保存并运行、重跑、情景测算，运行时显示正在做什么，按钮锁住。运行结果提示移到设置区外面，设置区折叠后仍然看得到。

### P1

5. 版本号改成「第 N 版 · 日期时间」，完整 ID 放进可复制的版本信息。枚举值只显示中文，`pending` 改「待确认」。补 P&L 列名映射。
6. 文稿页只放正文。重要性阈值、财务背景、引用依据、质量明细合并成「发布前检查」面板。正文标题下只留一行检查结果。
7. 成果库换列为 标题 / 任务 / 期间 / 类型 / 状态 / 时间。会话、大小、摘要挪进详情的技术信息区。「把这个窗口出成表格」改「导出 Excel」。

### P2

8. 页签计数改成和面板一致。现在计数统计全部分析的业务运行，面板显示选中版本，选中版本没运行时会出现「计数 4、面板写尚未运行」。
9. 资料页先放「这批资料能算什么」，再放文件卡片。待确认的表结构做成待办项。

## 4. 等待态效果

只在超过 2 秒的等待上加效果。DESIGN.md 的金色只用于位置、选择和焦点，所以只选中性的 Thinking orbs，Border beam 只用 mono。装包前先问用户。

| 位置 | 效果 | 前提 |
| --- | --- | --- |
| 财务运行（P0 第 4 条的状态） | orbs `solving` 20 | 实测超过 3 秒再加 mono beam 包结果区 |
| 考核调整重算 | orbs `solving` 20 | 已有「重算中…」文字 |
| 文稿质量检查中 | orbs `searching` 20 | 已有检查中状态 |
| 文稿导入、OCR、导出进度条 | orbs `working` / `composing` 20 | 已有阶段文字和取消按钮 |
| 冷启动 | orbs `connecting` 20，替换旋转图标 | 无 |

仓库里测过的查询在 1.1 到 1.3 秒之间，用的是合成资料（`docs/finance/r2-performance-optimized-evidence.json`）。华宸真实工作簿的财务运行时长没测过，加 beam 之前先打点。

2026-09-27 用户同意安装。装的是 `thinking-orbs` 0.3.2，MIT 协议，无运行时依赖，锁定版本，和 `lucide-react` 一样放在 devDependencies，由 Vite 打进界面包。上表五处都已接入，统一走 `WaitOrb`。等待满 2 秒才出现，冷启动页不等。画布对读屏隐藏，状态由旁边的中文文字承担。减少动态效果时停在一帧，深浅色跟随 `data-theme`。原来的旋转图标和 `fnd-spin` 样式已删。Border beam 没装。

## 5. P0 实施记录（2026-09-27）

分支 `codex/results-conclusion-first`。

| 条目 | 做了什么 | 没覆盖的 |
| --- | --- | --- |
| 1 重排 | 有结果时财务口径设置移到结果下方；考核调整、归档图改折叠，摘要写条数；没结果时设置在上，范围字段只露期间，其余进「更多范围」；结果区加「调整口径」按钮打开设置；顺手把考核调整里的 `pending` 改成「待确认」 | 无 |
| 2 结论条 | 预算桥结果顶部显示利润变化、三项驱动、`interpretation`；优先用后端写好的短语，缺了才按金额字符串的正负号拼，不做运算 | 华宸真实任务全部是脚本运行，没有一条预算桥，结论条在真实数据上不出现。脚本长表的结论要另做，见下 |
| 3 状态汇总 | 文稿质量检查首屏一行列待处理项，7 项明细收进「核对明细」 | 运行头的 4 个状态标签没动 |
| 4 运行中状态 | 财务口径的保存、运行、重跑、情景测算、保存映射显示正在做什么并锁按钮；结果提示移到设置区外 | ERP 来源刷新、工作簿写回、表结构确认还没做 |

验证结果如下。前端 661 个测试通过，新增 9 个在旧代码上全部失败。构建通过。开发版对照华宸数据副本截图确认了分析结果页顺序和文稿检查汇总。

独立审查找出 7 条，这一轮全部修掉，测试增到 666 个。

| 审查发现 | 修法 |
| --- | --- |
| 「调整口径」打开的是最新口径，不是这条结果用的口径 | 按钮带上运行的 `finance_context_id`，打开时选中该口径并把范围填回表单，焦点移到设置标题 |
| 考核调整、归档图读取失败时，报错被折叠 | 报错和提示移到折叠区外，外层恢复 `aside` 地标 |
| 结论条漏算不完整的组；空维度值会把两组并成一组 | 组数按全部分组算；同一组出现两条利润行时不出结论 |
| 按组织和期间分组的预算桥，后端短语没有单位 | 行上没有单位时取两侧范围声明的单位；两侧不一致就不出结论 |
| 切页签会清掉运行中状态，按钮重新可点 | 运行中状态提到页面一层并按任务区分；口径列表、情景列表、映射字段、考核调整、归档图一并锁住 |
| 测试断言弱于测试名 | 补切页签后再点不会发第二次运行、重新挂载不会重开设置两条，并用改坏代码的方式确认能抓到 |

下一步最值的一条是脚本长表的结论。华宸这类任务的结果是 `scenario` 加 `value` 的长表，情景名带期间后缀。先让情景识别认出 `actual_1_8` 这类写法，关键数卡片就能出来，再补列名映射。

## 6. 验收标准

- 1280×800 下，有成功运行的任务打开分析结果，不滚动能看到结论条。
- 分析结果首屏默认只露版本选择一个表单字段。
- 默认视图没有 12 位 ID、英文枚举、英文列名（P1 完成后）。
- 超过 2 秒的操作，300ms 内出现运行中文字。
- 四个状态在数据层仍分开记录，现有状态测试不改期望。
