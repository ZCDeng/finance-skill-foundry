# FA Foundry UI 与交互设计优化提案

> 后续状态（2026-09-06）：用户已批准按本提案落地，操作界面字体指定为 HarmonyOS 或 Noto。实施采用 Noto Sans SC；下文保留提案阶段的分析语境，最终取值与验证结果以 [UI 实施记录](2026-09-06-ui-execution-log.md) 和 [设计约定](../../DESIGN.md) 为准。

建议采用一个持续工作的任务空间：左侧选择任务，中间与助手讨论，右侧阅读和修改资料、结果及文稿。保留现有品牌辨识，让财务数据、当前口径和下一步操作成为页面主角。

本提案按照 Impeccable 的 shape 流程形成。产品方向沿用用户已确认的“财务分析优先、财务经理主导判断、开放 harness、保留建账和资金管理扩展”。统一工作区的方向已经确认，具体区域布局、尺寸及视觉调整仍为推荐值。本轮不修改 UI 代码，不生成 DESIGN.md 或写入长期构建偏好。

本轮用户进一步确认：“与助手持续讨论，同时查看结果”，并选择“统一分析、对话、资料与成果的工作区”。因此对话常驻、成果可同步查看及统一工作区，是本提案确定的使用目标；具体布局和视觉仍待评审。

## 1. 真实界面暴露的问题

本轮读取实际组件和 pinned DSH 客户端，使用当前打包应用、隔离的合成资料测量 1440×900 与 1280×800 逻辑视口，并查看浅色、深色及原生对话界面。未调用模型处理真实财务资料。

| 现状 | 对财务经理的影响 | 优先级 |
| --- | --- | --- |
| 顶层“分析 / 对话 / 数据台 / 任务 / 交付物”，分析页又有四个页签；进入对话会隐藏分析页 | 看数字、追问和检查文稿不断切换，难以持续工作 | P0 |
| 1280×800 下结果面板从 y=865.49 才开始；标题、输入框、分析定义排在结果之前 | 点击“分析结果”后，首屏仍看不到计算值 | P0 |
| 新任务添加资料路径不保留完整未发送问题；任务切换还会清空本地问题状态 | 写好的问题可能丢失，用户需要重述 | P0 |
| 文稿和分析定义允许本地编辑，但交给助手时主要传保存对象的 ID | 用户看到的新内容与助手读到的版本可能不同 | P0 |
| 壳和原生助手各有导航、标题及输入区域，视觉语言也不一致 | 用户需要理解两套界面，发送和上下文的归属不清楚 | P1 |
| 结果表格默认左对齐，参数名称可能只是“第 1 项”，假设描述与实际参数绑定不明确 | 比较金额费力，也容易误以为改说明就改变了计算 | P1 |
| 文稿以大文本框呈现，保存、归档及两种导出并列 | 阅读和交付路径不突出，编辑状态容易成为额外门槛 | P1 |
| 已保存的方法与当前资料、结果、文稿常驻同级 | 复用管理占用当前任务空间，主次不够清楚 | P2 |

主要代码依据：[应用路由](../../app/src/App.tsx)、[应用壳](../../app/src/components/Shell.tsx)、[分析工作区](../../app/src/views/Analysis.tsx)、[通用控件样式](../../app/src/components/components.css)、[原生视图尺寸](../../app/electron/harness/bounds.ts)。

测量与截图保存在 `build/ui-design-review/`，该目录是本地评审证据，不作为产品构建输入。这里的数值针对本次合成任务，不代表每一种数据状态的布局高度。

## 2. 推荐的信息架构

### 一个任务，一个持续工作的空间

```text
┌─────────────┬──────────────────────────────────────────────────────┐
│ 新建任务     │ 华东利润分析        期间 · 币种/单位       任务操作 ⋯ │
│ 搜索任务     ├───────────────────┬──────────────────────────────────┤
│              │ 持续对话          │ 资料  /  分析结果  /  文稿        │
│ 最近任务     │                   │                                  │
│ · 华东利润   │ 问题、解释、       │ 当前结果 / 数据表 / 文稿          │
│ · 回款预测   │ 运行与工具反馈     │ 修改口径、比较版本、查看依据       │
│              │                   │                                  │
│              │                   │                                  │
│ 方法库       ├───────────────────┤                                  │
│ 设置         │ 唯一输入框 + 附件  │                                  │
└─────────────┴───────────────────┴──────────────────────────────────┘
```

该示意图表示区域职责，不是已确认的视觉稿。

- **任务栏**：新建、搜索、最近任务；方法库和设置作为次级入口。任务标题可以修改。
- **任务头部**：当前业务问题、真实可用的期间/币种/单位信息，以及正在执行的工作。元数据不明时允许空缺或明确“未指定”，不猜测填满。
- **对话区**：唯一持续输入入口。结果、选中明细和文稿可以带着明确版本进入追问；助手解释和运行反馈在这里连续呈现。
- **成果区**：资料、分析结果、文稿。独立滚动，切换内容不卸载会话。保留当前筛选、选中行、编辑状态和滚动位置。
- **方法复用**：在有用的分析上提供“保存为分析方法”；方法库负责查找、说明输入要求与创建后续任务。
- **数据台与既有交付物**：数据台从当前资料或结果进入；已有归档成果在相应任务内查看，另保留跨任务成果检索入口。旧功能和历史记录保持可达。

### 按桌面窗口调整工作密度

| 窗口 | 推荐布局 | 用户可控操作 |
| --- | --- | --- |
| 1440×900 及以上 | 任务栏约 180–200px；对话约 400–460px；成果使用余宽 | 拖动分隔条；收起任务栏；对话专注/成果专注 |
| 1280×800 | 默认收起任务栏；对话与成果并排 | 随时调出任务抽屉，不离开当前工作 |
| 当前最小窗口 1080×720，或放大后可用宽度不足 | 默认以成果为主，对话通过同任务切换或专注视图打开 | 一键返回原位置；不丢输入、选中与滚动 |

尺寸是待验证的起点。400–460px 对话区须通过原生客户端适配和完整工具交互验收后才能成为默认布局。当前应用面向桌面，不在这轮虚构移动端适配承诺。

## 3. 重排财务经理的连续操作

### 从问题和资料开始

空任务只有简短起步提示、问题输入和添加资料。可提供三条简短示例，点击只填入输入框，不自动执行。已有任务打开到最近工作位置；执行中的任务保留当前运行状态。

问题与附件属于同一份起步草稿。打开文件选择器、取消选择、导入失败或切换页面，都不清空问题。任务标题只是摘要，不能充当原始问题的存储位置。

首次发送先完成任务与会话绑定，再把完整问题及附件提交一次。重复点击、恢复连接与重试不能重复发送。进入任务后使用同一个原生输入框，取消“壳里写一遍、助手里再发送一遍”的日常路径。

### 添加资料后，先知道能用什么

资料列表优先展示名称、用途、可用表/字段、行数和导入状态。期间、币种、单位和粒度在有明确记录时展示，缺项可以由经理填写或更正。

当前格式能力按实际列出：CSV、XLSX、JSON、Markdown、TXT。PDF/图片解析未实现，不显示可用上传入口。自动识别财务字段与业务口径需要新增能力，不能用界面文案假装已经具备。

导入失败显示具体文件、失败原因和重试动作；已成功导入的文件继续可用。源表和转换后的资料分别可查，避免把文件名当成财务定义。

### 先看到结果，再按需要检查定义

选择“分析结果”后，首屏优先出现：分析标题、期间/单位、当前计算值或表格、使用的假设提示，以及“调整口径 / 比较版本 / 查看依据”。没有结构化指标时显示实际结果表，不自动编造收入、利润、增长率卡片。

查询定义和脚本移入“查看依据”，历史运行放入版本列表；失败的新运行不会覆盖成功的旧结果。旧结果仍可阅读，同时明确其输入和口径版本。

金额右对齐、按列统一精度，表头或数值附近标明单位。比例与金额分开，负数与异常通过符号和文字说明；不单靠红绿判断。宽表支持局部横向滚动和固定关键列，复用现有分页，不让整页跟着表格横向移动。

### 让“调整口径”对应真实计算

优先呈现业务字段，例如地区、期间、分摊方式、回款率；字段类型、单位、范围和与计算参数的绑定需要真实元数据。现有定义缺少元数据时，继续提供明确的参数/SQL 高级编辑入口，不能仅将“参数 1”包装成推测的业务名。

假设说明与计算参数分开表达。只修改解释文本，不显示“计算已更新”。计算相关输入变更后，保留旧结果并标记“口径已改，待计算”；主按钮变成“按新口径计算”。用户点开即可比较两次运行的真实输入和结果。

新增业务元数据采用可选、兼容字段，既有分析与方法仍能读取。方法复用时区分公式常数、业务假设和数据绑定，避免把 SQL 中所有数字都变成经理需要填写的参数。

### 一次点击检查数字的来历

结果或文稿中的数值若有可解析依据，点击后在成果区打开局部抽屉，依次展示来源定位、计算定义、相关假设和运行版本。没有行级依据时如实展示已有的快照/运行级信息，不能伪造精确追溯。

“围绕这一项追问”把选中对象和确切版本送入同一输入框，附上可移除的上下文标签。未保存的编辑以工作副本快照传递，或先保存再绑定返回的新 ID；不能悄悄引用旧版本。关闭抽屉后回到原选中行和阅读位置。

### 文稿以阅读和交付为中心

文稿提供阅读与编辑状态，正文为主要区域；来源和版本按需展开。当前大文本框仍可作为低成本编辑基础，先提供受控 Markdown 预览，无需本轮引入完整富文本编辑器。

“导出”是主要动作，菜单选择 Markdown 或 XLSX；导出当前修改时先保存确切版本，再导出该版本，显示成功路径或失败原因。保存失败不能继续导出旧稿并宣称成功。已保存草稿可以直接导出，归档是独立的选定版本动作。

用户编辑状态在任务内恢复；正式分析和成果版本维持不可变。输入过程中保存工作副本，不按每次按键创建正式归档版本。已归档稿修改时清楚提示将形成后续版本。

### 展示真实能力与运行进度

查询、计算、脚本和子任务以可展开的运行条目出现，默认给出目的、状态、结果和停止/重试等可用动作。代码、调用参数、详细日志留在展开层，用户可以查看。

后台工作不阻塞资料阅读和文稿编辑。没有可测进度时显示运行状态与已完成步骤，不编造百分比。失败局限在受影响的操作；模型服务暂不可用时仍能查看本地成果，修复连接后继续原任务。

用户可以改变分析方向、保留专业判断、导出未阅稿。执行成功、可复算、经理认可和已归档保持独立；高频界面展示当前相关状态，其余按需查看，不能合并成一个“已验证”绿标。

## 4. 视觉与控件方向

采用 Impeccable 的 Operate 使用方式：让重复工作的速度、清楚的状态和稳定的位置优先。沿用 FA 标识、克制的中性色和少量金色强调，以下视觉值是建议，不是已锁定的设计规范。

| 层面 | 推荐调整 | 目的 |
| --- | --- | --- |
| 排版 | 任务标题约 20–24px，操作与表格约 13–14px，对话/正文约 15–16px | 减少大标题挤占结果，提高工作密度 |
| 字体 | 常用控件与财务表格使用系统无衬线中文；评估霞鹜文楷转为可选阅读风格，Asap 可保留品牌用途 | 长时间扫读和数字比较更稳定；不新增字体依赖 |
| 数字 | 等宽数字、按类型对齐、明确币种和单位、尊重真实计算精度 | 避免漂亮排版掩盖口径差异 |
| 色彩 | 中性色承担主体，金色用于选中与定位；危险、异常有独立语义 | 让数据与操作层级更清楚 |
| 容器 | 减少嵌套卡片和大圆角输入容器；以分区、间距和细分隔线组织内容 | 为表格、文稿和对话留出实际空间 |
| 控件 | 每个上下文一个明确主动作；保存状态、次要动作与更多菜单分层 | 避免每行出现四五个同等权重按钮 |
| 深浅主题 | 同一套层级语义分别配色；输入、禁用、焦点和错误均独立验证 | 两种主题下操作含义一致 |
| 动效 | 面板展开和状态过渡短促；尊重减少动态效果设置；后台刷新不移动焦点 | 保持位置可预期，不打断阅读 |

截图中字体确实是现有打包字体，不把个人审美偏好写成可读性测试结果。新字体取舍在静态视觉评审时对同一张财务表进行对照确认。

## 5. 原生 harness 嵌入的实施前提

统一工作区复用当前 runtime、流式消息、工具执行及输入状态机。主要工程约束来自 DSH 的布局和 Electron 原生视图层级。

| 核实的约束 | 方案要求 |
| --- | --- |
| 当前原生视图占用顶部 100px 以下的整窗；进入对话会隐藏 Analysis | App 合并工作区路由，bounds 接收受约束的目标矩形，原生会话保持挂载 |
| 原生 sidebar 收起仍占 56px；公开 sidebar 插槽只替换内容 | 仓库内维护可复现的局部布局适配，真正提供嵌入模式的零宽导航列 |
| 工具 details 布局最低约需 996px；400–460px 时现有算法把它压至 0 | 在对话 pane 内改成可达的抽屉/内容视图，或明确展开到专注视图；工具详情可达是上线条件 |
| 400–460px 能收缩，但 sidebar 与正文边距会使实际文字区仅约 280–340px | 一并处理边距、空态与控制条；以完整交互状态验收，不能只看输入框是否能打字 |
| 官方支持 session header 与 composer 插槽，但没有现成 compact hero/headline 开关 | 标题栏使用公开插槽；空态和布局做局部 client 适配，保留原生 composer 行为 |
| WebContentsView 不能被 React z-index 或 portal 遮盖 | 全局弹窗显式控制原生视图隐藏/恢复；pane 内菜单不得被矩形裁掉 |
| 当前 host.show 写草稿会重载页面；成果更新主要靠返回页面重读 | 使用受限会话/输入适配通道，保留冷启动恢复；加成果变更通知或有界刷新，避免频繁 reload |

不直接修改安装目录中的 node_modules 作为交付，不堆叠 DOM 隐藏选择器替代布局契约，也不重写成熟的聊天协议。具体采用官方插件还是仓库内可重放补丁，由 pinned 客户端支持面决定；保留版本锁定和重放检查，不引入新依赖。

技术依据：[公开布局类型](../../app/extra/dsh/node_modules/@deepseek-ai/dsh-client-ui-layout/lib/types/client/index.d.ts)、[布局计算](../../app/extra/dsh/node_modules/@deepseek-ai/dsh-client-ui-layout/lib/client.js)、[输入动作契约](../../app/extra/dsh/node_modules/@deepseek-ai/dsh-client-ui-conversation/lib/types/client/input/contract.d.ts)、[host](../../app/electron/harness/host.ts)、[pane](../../app/electron/harness/pane.ts)。客户端依赖路径供本机复核，不作为仓库文档的唯一依据。

## 6. 分阶段落地顺序

| 阶段 | 工作 | 完成判据 |
| --- | --- | --- |
| A：修复连续操作 | 先补问题/附件、未保存修改传递、导出确切版本等回归保护；再修复状态管理；将实际结果前置 | 提问不丢失、助手读到当前修改、导出版本正确，1280×800 首屏看到已有计算值 |
| B：建立统一工作区 | 验证原生紧凑嵌入；合并分析/对话路由；三栏与收起/专注视图；唯一输入；持续刷新 | 窄 pane 中工具、菜单、中文输入可用；任务切换无串数据、丢草稿或重载会话 |
| C：整理财务操作 | 结果/版本/依据抽屉；业务参数元数据；文稿阅读编辑与导出菜单；方法保存与复用 | 每个显示值、假设和版本对应真实对象；已有定义及历史记录兼容 |
| D：统一视觉并验证 | 应用与原生区的字体、间距、颜色、控件层级；浅深主题、键盘、缩放及复杂状态 | 通过下列场景验收，再更新 DESIGN.md 与执行记录 |

清理顺序：先保护跨页面状态和已有任务绑定行为，再删除重复输入及重复导航，最后拆分 Analysis 中结果、定义、文稿等职责。优先复用现有组件、桥接、状态字段和数据接口；不要同时重做计算服务。

主要涉及文件：`app/src/App.tsx`、`app/src/components/Shell.tsx`、`app/src/views/Analysis.tsx`、`app/src/styles/tokens.css`、`app/src/components/components.css`、`app/src/views/analysis.css`，以及 `app/electron/harness/` 的布局、生命周期和输入衔接。业务参数与工作副本支持需要同步评估 IPC 和 foundry 数据契约，不能当成纯 CSS 改动。

## 7. 可观察的验收标准

1. **结果首屏可见**：在 1280×800，已有成功结果的任务切到分析结果，无需整页滚动即可看到实际值或首行结果、单位与相关期间，以及下一步操作。长查询默认收起。
2. **输入不丢**：完整问题超过任务标题长度时，添加/取消资料、部分导入失败、切任务再返回均保留；首次提交仅产生一条用户消息。
3. **上下文准确**：在任务 A 修改口径/文稿后追问，助手取得该工作副本或确切新版本；切到 B 再返回，输入、选中对象和结果不串任务。
4. **运行不抢工作**：计算完成更新相关结果，正在编辑的正文、焦点和滚动不变；取消及重试显示真实生命周期。
5. **工具始终可达**：400px、460px 和专注宽度检查长模型名、附件、ask_user、工具授权、停止、队列、代码块、宽表及工具详情。任何被裁切或压成零宽的关键操作均不通过。
6. **层级与拖动可靠**：主窗口弹窗、pane 内菜单、分隔条拖动、窗口 resize、缩放后仍正确命中；关闭弹窗恢复原会话及焦点。
7. **计算状态真实**：修改说明不会伪装成重算；修改参数不会复用旧“可复算”状态；版本比较只显示实际记录的输入和输出差异。
8. **导出等于所见版本**：修改后直接导出，成功文件对应刚保存版本；保存/导出失败不会回退旧稿却提示成功；导出不强制归档或经理认可。
9. **表格可用**：长列名、20 列宽表、分页结果、小数、零、负数与缺值均可区分；单位不缺失，精度不因显示而被无提示改变。
10. **键盘与中文输入可用**：页签、菜单、抽屉、分隔条和专注切换具有明确焦点；中文 IME 选词回车不发送；支持稳定的发送快捷键；放大到 200% 可切换工作区完成关键操作。
11. **浅深主题可读**：文字、输入边界、焦点、禁用态、错误和选中态分别检查；不单靠颜色传递数值或运行状态。
12. **空态与异常可恢复**：无资料、无结果、多版本、失败导入、运行失败、服务暂不可用及长标题任务，都有具体下一步，已有本地资料仍可阅读。

实施时运行相关 UI/桥接/任务隔离回归、类型检查、构建及静态检查；最后使用真正打包应用分别采集壳与 native pane 的可视证据。当前提案未改代码，因此本轮不重跑完整实现测试，也不把过往测试当作新布局的验证。

## 8. 扩展边界与待评审选择

建账、资金管理未来可以成为工作区类型，复用任务、资料、对话、运行和成果区域。领域准备好时再加入科目/凭证、银行账户/资金计划等专属对象与动作。本轮不添加不可用的导航占位，也不把现金预测操作包装成实际支付。

统一工作区与持续讨论并同时查看结果的方向已经确认。建议继续评审对话与成果的具体布局及宽度、系统无衬线字体用于操作界面、方法库降为次级入口。本提案结合用户回答与既有任务工作区方向提出推荐，不能视为全部设计细节已批准。

剩余主要风险是：DSH 紧凑布局的维护成本；业务参数语义需要新增兼容数据支持；自动保存工作副本与不可变正式版本必须明确分离。上述风险都有对应阶段和验收要求，不以视觉效果图代替实现可用性。

本轮输出：确认事实的 PRODUCT.md、本设计提案、本地截图和测量证据。UI、运行时及数据代码保持本轮开始时的状态。
