# 分析页面向财务经理的交互收敛 · 设计交接

用户是财务经理，不是工程师。他打开分析页要做三件事：把资料加进来、确认这次按什么范围算、看结论并决定要不要查依据。本文记录 2026-09-27 对分析页全量代码的逐行阅读结论、据此定下的设计方案、落地后的组件与文案对照，供设计与前端后续接手。

[09-27 结论优先方案](2026-09-27-ui-conclusion-first-proposal.md) 解决了「结论压在下面」。本文接着解决剩下的三类问题：词不是经理的词、范围要经理手工填、编号和过程混在结论旁边。

## 1. 问题清点

逐块读了 `app/src/views/Analysis.tsx` 与 `app/src/views/analysis/` 下全部组件。问题归为三类，每类给证据与对经理的影响。

### 1.1 用词是引擎的词

| 证据 | 对经理的影响 |
| --- | --- |
| 按钮写 `保存并运行 P&L`、`运行预算桥`、`用已保存口径重跑 P&L`；面板标题 `财务业务口径` | 经理不知道 P&L 与预算桥对应哪张表 |
| 运行记录分成 `业务 / 活动 / 失败`，历史摘要写「运行历史 · 业务 2 · 活动 5 · 失败 1」 | 「活动」是助手的探查，经理以为是自己该看的东西 |
| 状态词 `已运行 / 运行中 / 运行成功`；差异比较写「后端未找到可比的上一次运行」 | 「运行」「后端」都不是经理的语境 |
| 引擎错误原句直接抛给界面（英文、带 32/64 位编号） | 看不懂，也不知道下一步该做什么 |
| 情景、币种、单位靠手输：`actual` `budget_ytd` `CNY` `万元` | 拼错就算不出来，错误还是英文 |
| 科目类型下拉是 `revenue / cost / expense`，来源刷新写 `snapshot_only / business_key`，账套字段叫 `tenant` | 同一个概念在不同面板叫法不同 |
| 各处 `x instanceof Error ? x.message : String(x)` 分散在十几个组件里 | 文案改不动、口径不统一 |

### 1.2 范围要填四遍，而且靠手输

| 证据 | 对经理的影响 |
| --- | --- |
| 四处独立的范围表单：资料页 `AnalysisScopeCard`、结果页 `FinanceWorkbench` 的口径设置、`RequirementsPanel` 的范围块、`FinanceBackgroundPanel` 的适用范围；字段名、顺序、默认值各不相同 | 同一个「2026-08 · 华东 · 万元」要填四次，还可能填得不一样 |
| 全部是文本框；就绪报告与文件标题行已经读出了期间、单位、币种，界面却不提供 | 经理要自己去看文件抄一遍 |
| 空值写成「待经理确认」这样的字符串存进记录 | 记录里混进了界面占位词 |
| 期间冲突（共同期间与逐项期间不一致）的处理按钮写「移除共享期间」 | 「共享」是实现词 |

### 1.3 编号、摘要、过程和结论放在一起

| 证据 | 对经理的影响 |
| --- | --- |
| 版本、文稿、资料、计算、映射的下拉 meta 都带 12 位 `shortSha` | 像开发工具；两个版本靠编号区分，而不是靠「第几版 · 什么时候」 |
| 依据面板里「资料标识与摘要」「运行标识与结果摘要」直接列 32/64 位字符串；下钻来源写「来源摘要：{hash}」 | 经理核对依据时被一串字符打断 |
| 运行历史把助手的中间探查与结论并列 | 经理不知道哪一条是「答案」 |
| 就绪面板写「文件身份策略：按快照整份替换」；来源刷新批次写「新快照 3f9a…」「沿用 a7c1…」 | 术语加编号，两重看不懂 |
| `调整口径`、`口径与计算定义`、`与助手调整口径`、`高级：查看计算口径` | 「口径」既指范围也指计算方式，含义漂移 |

## 2. 设计原则

1. 经理只看到业务词。引擎的词（P&L、bridge、run、activity、hash）在界面上不出现；需要保留的原句作为「系统提示」附在中文句子后面。
2. 一个任务只有一份范围。哪里编辑都是同一条记录，保存一次，之后的计算与文稿都读它。
3. 能读出来的不让经理填。文件、就绪报告读到的值先给出来，经理点一下采用；固定枚举用下拉，不手输。
4. 结论、依据、过程三层不混放。编号与摘要属于过程层，收进一处，默认折叠，但保持可复制、可精确核对。
5. 只改显示，不改数据。执行 / 可复算 / 阅核 / 发布四个状态、Decimal 字符串不经 `Number`、拒绝语不翻译，这些约定沿用。

## 3. 方案

### 3.1 对外词表与错误文案映射

新增 `app/src/views/analysis/glossary.ts`，是分析页唯一的对外词表：

| 导出 | 用途 |
| --- | --- |
| `SCENARIO_OPTIONS` | 范围里的情景下拉：实际 / 预算 / 预测 / 累计实际 / 累计预算，meta 写业务解释（账面发生数、批复预算…） |
| `RESULT_SCENARIO_OPTIONS` | 分析要求里的结果情景，另加 单月实际 / 单月预算 / 上年同期实际 / 差异 / 达成率 |
| `CURRENCY_OPTIONS` / `UNIT_OPTIONS` | 币种（label 人民币，meta CNY）、单位（万元 / 元 / 千元 / 亿元） |
| `scenarioLabel(value)` | 任何情景代码 → 中文；认不出的原样返回 |
| `RUN_ROLE_LABELS` | `business → 结果`，`activity → 中间步骤`，`failure → 未完成的计算` |
| `friendlyError(message)` | 按规则表把引擎错误翻成经理能读的句子，原文附在「（系统提示：…）」里，其中 64 位摘要替换为「（摘要已省略）」、32 位编号替换为「（编号已省略）」；已经翻过的句子不再翻（幂等） |
| `errorText(failure)` | 统一替代 `x instanceof Error ? x.message : String(x)` |

`shared.ts` 的 `unwrap()` 统一套用 `friendlyError`，因此走 `unwrap` 的每个调用点都自动得到中文错误。`views/` 下所有组件的 catch 分支改用 `errorText`。

### 3.2 一个「分析范围」

**数据流。** `useAnalysisScope(taskId, question, datasets)`（`scope.ts`）由 `Analysis.tsx` 持有一次，往下传：

```
Analysis.tsx ── useAnalysisScope ──┬── 资料页  ScopePanel（完整编辑，保存范围）
                                   └── 结果页  FinanceWorkbench → ScopeFields（同一份字段）
```

- 读取：任务切换时调 `analysis-requirements-list` 取当前记录（`{question, scope, bindings, items}`），并顺带调 `finance-readiness` 作为候选值来源（失败即忽略，不影响主流程）。
- 候选：`inferScopeCandidates(datasets, report)` 从每份资料的 `metadata[key]`、`metadata.scope_hints`、就绪报告的 `proposed_scope` 与各资料 `scope` 里收集期间 / 组织 / 单位 / 币种 / 情景 / 账簿 / 粒度的候选值，去重。
- 保存：`save()` 写 `analysis-requirements-save`，带 `parent_id`（CAS）、保留 `question`、`items`、`bindings` 和记录里不属于七个范围键的其他键；空字段不写入（不再有「待经理确认」这样的占位串）。保存后字段以服务端返回的记录为准，避免把服务端已丢弃的旧键再次发回。
- 冲突：`scopeConflicts(items, scope)` 在共同期间 / 组织 / 情景与指标逐项列出的值不一致时给出提示，保存按钮禁用，提供「清空共同期间，保留逐项期间」一键处理。

**界面。** `ScopePanel.tsx`：

- 每个字段下方一行「资料里读到：」，每个候选值是一个小按钮（`aria-label="采用资料里的期间 2026-08"`），点一下填入；已采用的值不再出现。
- 期间用 `AccountingPeriodInput`（含上期 / 上年同期快捷键）；若已保存的是一段说明文字（如 `2026-01:2026-08`），退回文本框并说明可改为 YYYY-MM。
- 单位、币种、情景用 `SearchableSelect`，空值显示「待确认」；固定词表之外，资料里读到的值以 meta「资料里读到」列入，已保存但不在词表里的值以 meta「已保存的值」列入，保证任何记录都能被显示和保留。
- 主字段：期间 / 组织 / 单位 / 币种 / 情景；账簿 / 粒度收进「更多范围」折叠，摘要行写出已填值。
- 结果页 `FinanceWorkbench` 改为「计算设置」折叠区：实际资料 / 预算资料（可选）/ 已保存的范围三个下拉，随后是同一组 `ScopeFields`（期间 / 组织 / 单位主显示，币种 / 情景 / 账簿在「更多范围」）。计算按钮为 计算损益表 / 计算预算差异 / 按已保存范围重算损益表 / 按已保存范围计算预算差异。计算时把范围字段写成 finance context；未填的字段按「资料里唯一的候选值 → 引擎默认（CNY / 元 / actual）」补齐。
- `RequirementsPanel`、`FinanceBackgroundPanel` 的范围字段不再独立展开，折叠为一行「范围 · 期间 2026-08 · 组织 华东 · …」摘要；说明文字指向资料页的「分析范围」。
- 删除 `AnalysisScopeCard.tsx`。

### 3.3 结果页收敛

结果页在 09-27 方案后已是「结论 / 差异表 → 依据 → 计算定义（折叠）→ 计算设置（折叠）」，本次不再动块的顺序，只收敛折叠层内的内容。

- 新增 `TechnicalInfo.tsx`：`<details class="analysis-details analysis-technical"><summary>技术信息</summary><dl>…</dl></details>`，默认折叠，等宽字体，可复制。空值行自动省略。
- 依据面板：每份资料的「资料编号 / 资料摘要」、本次计算的「计算编号 / 结果摘要」、下钻来源的「来源摘要」全部进 `TechnicalInfo`。正文只剩资料名、原始文件名、参数、假设、计算范围。
- 计算范围以中文显示：情景别名用 `scenarioLabel`，字段名用「账簿 / 组织 / 期间 / 币种 / 单位 / 情景」。
- 计算历史：摘要写「计算历史 · 结果 N · 未完成 N」，只列结果与未完成的计算；助手探查收进嵌套的「中间步骤 · N」，并说明「它们不是结论，文稿也不会引用它们」。
- 版本区分统一用「第 N 次计算 · 时间」「第 N 版 · 时间」，不再显示哈希前缀；分析版本、文稿版本、资料、已保存范围、管理科目映射、情景资料别名的下拉 meta 全部去掉 `shortSha`。
- `调整口径 → 调整范围`；`口径与计算定义 → 计算定义`；`与助手调整口径 → 与助手调整计算方式`；`高级：查看计算口径 → 高级：查看计算定义`。
- 资料预览、来源刷新、工作簿写回、可引用事实、就绪面板的编号与策略措辞同样处理（见对照表）。

## 5. 组件与约定

| 组件 | 位置 | 备注 |
| --- | --- | --- |
| `glossary.ts` | `views/analysis/` | 词表与错误映射；新增文案先查这里 |
| `scope.ts` | `views/analysis/` | `useAnalysisScope`、候选值推断、冲突判定；不含渲染 |
| `ScopePanel.tsx` | `views/analysis/` | `ScopeField` / `ScopeFields` / `ScopePanel`；`ariaPrefix` 决定无障碍名（资料页为「分析范围期间」等，结果页无前缀） |
| `TechnicalInfo.tsx` | `views/analysis/` | `rows: [label, value][]`，空值自动省略 |
| `.analysis-technical*`、`.analysis-history-steps` | `views/analysis.css` | 12px 灰字，dd 等宽 |

无障碍名约定：`SearchableSelect` 的触发按钮 `aria-label = ariaLabel ?? label`；候选值按钮 `采用资料里的{字段} {值}`；清空按钮 `清空{字段}`。测试按这些名字定位。

不做的事：`App.tsx` 的 `Refusal` 按其注释保留原句（拒绝语不得翻译）；金额不经 `Number`；四个状态字段仍分开记录。
