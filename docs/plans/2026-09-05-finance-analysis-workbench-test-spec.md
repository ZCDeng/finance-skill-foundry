# 财务分析工作台实施与验收清单

本文是新版方案的验收设计，不是测试通过报告。现有测试结果见 `../reviews/2026-09-05-codex-review.md`。

## A. 先修复现有正确性问题

| ID | 情境 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | A/sessionA 导入中途打开 B/sessionB，然后恢复 A | 工具只访问 A；不依赖 global current；B 无变化 |
| A02 | 同时运行 A/B，子会话或未知 session 发起工具调用 | 已绑定子会话继承正确上下文；未知者拒绝且不写任何任务 |
| A03 | JSON 原始数字 token 为 900719925474099.99 | 解析到 Decimal 的值仍精确相等；禁止在构造测试数据时先转 float |
| A04 | 导出 123456789012345.67 和 1234567890.1234567 | 真实 save/load 后数值精确相等，或按明确约定存为原值文本 |
| A05 | 两次 record-reference 并发追加不同 id | 清单与底稿都保留两项，无成功但丢数据 |
| A06 | 引用追加与 emit-brief 同时执行 | 引用进入可追溯的稿/底稿版本，状态与引用记录一致 |
| A07 | North=70、South=30，问 North 占比 | 新计算输出 70%；旧接口明确其仅为汇总操作，不将 100 当占比答案 |
| A08 | 任意非空 SKILL.md 加合法 foundry.json | 只能证明契约检查与引擎自检；没有方法实跑不得显示“方法验证通过” |

实现这些修复前先加入复现测试；避免将现状错误输出写成新的期望行为。每项改动只修改其服务与测试，资源镜像与相关调用方同步。

## B. 第一个产品纵向闭环

固定合成数据，禁止依赖客户资料或模型编造期望值：

- 两期间、两地区、三个项目的收入/成本/费用明细；相同粒度的预算表；币种 CNY。
- 本月华东收入 120、成本 70、费用 20，利润 30；预算收入 100、成本 60、费用 15，利润 25。
- 上月华东利润 20；本月西南利润 10；所有金额使用同一注明单位。
- 一项客户重复映射，另有一个缺失预算项目，分别作为负向 fixture。

| ID | 用户操作 | 验收 |
| --- | --- | --- |
| B01 | 新用户加入上述文件，问华东利润为何超预算 | 无需写方法；实际 30、预算 25、差额 5、差异率 20%；收入贡献 +20、成本 −10、费用 −5，合计 +5 |
| B02 | 继续问环比以及是不是西南影响 | 环比 +10/50%；华东筛选未混入西南；依据包含实际比较期 |
| B03 | 去掉预算表 | 继续输出实际分析；预算比较标缺数据，不生成预算或中断所有工作 |
| B04 | 告诉助手总部费用 5 不计入管理利润 | 新口径利润 35，旧 30 可查看；调整记为用户口径，不改账面明细 |
| B05 | 追加收入成本清单后重跑 | 新 run 固定新快照；旧报告仍指原快照 |
| B06 | 打开已归档报告继续提问 | 带入报告具体版本与数据；可读底稿、检索、补资料、创建新版 |
| B07 | 编辑报告段落并导出 | 正文修改进入新 artifact；计算结果的引用不丢；手改金额解除旧校验标记 |
| B08 | 保存为方法，用另一套 fixture 再跑 | 复用指标/步骤/输出结构；不携带第一次的敏感内容与实际数值 |
| B09 | 加入 Markdown/TXT 经营说明，解释某项目成本异常 | 说明作为背景来源，引用文件 hash 与段落；不将文字假说当已证明的原因；未支持的 PDF/图片明确提示格式能力 |

“为什么”的因果解释必须区分数据分解与因果假说：数字桥接正确不代表已证明业务原因。用户可编辑判断和行动建议。

## C. 计算和数据合同

- 多表关联检查一对一/一对多/多对多，重复客户映射不会让收入翻倍；未匹配行保留可见。
- 混合币种需指定换算规则，汇率来源和日期进入依赖；单位不同显式换算。
- 期末余额不沿时间求和；期间发生额与时点余额分别定义。
- 比例的分母为零、负数、空值有可检查规则；不出现 NaN/Infinity 财务结果。
- 支持过滤、聚合、公式、比较、账龄与情景；问题文本不是实际计算式的替代品。
- 原始表被解析/清洗后保留转换记录、原始 hash 与定位；缺失公式缓存不能静默当零。
- 同输入、同代码/参数/环境的确定性计算可重跑；浮点统计按声明容差比较。

## D. 开放能力真实验证

| 能力 | 正例 | 负例/恢复 |
| --- | --- | --- |
| 文件 | 读取已加入任务的 workbook、合同、备注 | 未加入任务的目录不可经绝对路径或符号链接绕入 |
| SQL | CTE、连接、窗口函数对已绑定数据计算 | 外部文件读取、ATTACH、扩展加载、写出、多语句副作用按执行策略拒绝 |
| Python/shell | 在 scratch 清洗并生成图表 | 不可修改 canonical store、读取宿主密钥；超时杀进程树 |
| 子任务 | 并行分析地区并归并结果 | 不能扩展父任务资源；每个结果有 child run 和来源 |
| fork | 在同一任务分支研究不同假设 | fork 注册失败不留下可写的无归属会话 |
| jobs | 后台长算，查看状态，取消后重试 | 旧 job 不影响新 context；重试不重复归档 |
| Office | 草稿改公式/布局、另存新版本 | 归档工作簿字节不变；任意执行接口不能绕过 runner 边界 |
| 归档 | 多源计算引用正确的 run/output | 无真实执行记录不能取得可复算状态；手改值不继承校验 |

在真实 staged harness 上测试工具可见性、实际调用和上下文继承。注册成功与工具执行成功分别验收。使用非敏感 fixture，不读取用户其他项目或真实凭证。

## E. 兼容和扩展

- 所有旧窗口、结论稿、底稿及 XLSX 哈希保持不变且可读；原 CLI 契约有兼容测试。
- legacy period/f3 与新 analysis 不互相污染工具范围。
- method/plugin 的 canonical 与 packaged mirrors 一致；从 wheel 和冻结 CLI 分别验证新服务可用。
- 并发登记版本序号唯一；中断后可恢复；归档回执仅记录实际新版本。
- 关闭新入口后既有新成果仍可读，回退不删除资料。
- 建账扩展：凭证草稿不修改分析快照；过账前校验借贷、期间与科目；重复请求幂等。
- 资金扩展：现金预测不触发真实付款；提交与银行回执独立，超时先查询状态再决定重试。
- E 中领域用例在对应模块开工时实现；本轮不以空实现计为通过。
