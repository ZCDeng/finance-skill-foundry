# 物业财务套表真实交互验收与修复计划

用户授权：使用桌面两本财务工作簿跑完整交互。保留原文件，在独立应用任务中导入、提问、检查结果依据、调整假设、保存文稿并导出。

已复现：安装版 0.1.6 的“添加资料”把财务套表的封面第一行当字段名，报 column names must be nonempty and unique；两本表均未注册。当前普通单表 CSV/XLSX 的严格字段契约应保留，不能自动猜测财务表头或静默丢掉其他工作表。

修复顺序：
1. 先建立带封面、多工作表、合并表头的失败回归；新增完整工作簿快照注册路径，保留全部原始字节、摘要与工作表目录，普通明确表格导入保持兼容。计算仍通过显式绑定范围或隔离脚本读取，不能把工作簿直接当平面表计算。
2. 资料卡和预览清楚显示“Excel 工作簿”、工作表数量及可用范围；原生分析助手能够识别工作簿并读取原始快照，不从封面推断数据行。
3. 运行相关及全量回归，重新冻结 CLI、构建应用，先在隔离资料目录用用户原始文件验证导入及源摘要，再安装候选版。
4. 返回安装版重走同一任务：导入两表、真实模型分析、查看依据、修改情景、确认旧版本保留、导出并核对单元格。独立读取 Excel 的基线只用于验收，不伪装成应用的运行结果。

文件责任：后端实施负责 analysis_data.py / analysis.py / 后端导入测试；主线负责前端展示、分析助手说明、打包安装和 UI 验收。修复前已有本线程改动均保留；不增加依赖，不提交或推送。

追加已确认断点：AnalysisStore.run_script 永远保存空 result.rows，而 workbook_read 只返回临时 rows；脚本不能直接进入事实/草稿/导出链。新增可选 result_file，仅从该运行已校验、保留的 CSV/JSON 输出解析结果，保留输出摘要与 unverified 复现状态；不把计算结果自动标成原始行取证。补路径、格式、失败状态及文稿引用回归。

第三个真实交互断点：从资料页导入后，现有原生主会话的 snapshot_ids 仍为空；直接在原生输入框发问不会走 harnessOpen 的刷新。修复 IPC 导入成功后的主会话同步（部分成功也同步），不扩大子会话授权、不重绑旧运行；先用 UI 问题卡调用既有 analysis-refresh 恢复本轮真实分析，之后以新安装包复验自动同步。

真实文稿交互追加：原生模型保存包含6项分析要求、112条可引用事实的长文后，“本次分析要求”默认全展开，质量检查逐条铺开数百条同文案提示，使正文/导出难以到达。窄修复计划：文稿阅读时将要求编辑收进可展开区域；质量问题按类型、严重性、来源聚合，保留准确数量并可展开所有原始明细，默认显示摘要与少量具体例子；不降低质量检查标准、不抹去错误。另单独诊断脚本行级单位与单元格标记引起的真实/误报边界，先证据后修改。

范围编辑兼容修复：后端允许自定义指标、年度/期间说明和混合单位，但原生模型保存后，前端用固定下拉与单月输入将这些已保存合法值标成“失效”。保留已有值并明确显示自定义范围，标准新输入仍优先标准选择；不可自动归一化/丢失原模型口径。以保存往返测试验证。

后端质量误报证实及边界：仅修复 (1) 通用脚本 metric/label/value/unit 数值事实丢弃 row.unit；(2) 数字扫描把 04·合并利润表、01!O46 等来源引用识别为经营数字。先建立红灯回归并保留错误单位/真实无引用金额的检测。混合文本列不转为数字事实，脚本不自动获得标准财务要求闭环认证；这些限制保持。
